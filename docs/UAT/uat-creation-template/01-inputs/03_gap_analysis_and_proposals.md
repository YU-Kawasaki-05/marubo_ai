# 未決定事項の洗い出しと改善提案（Gap Analysis & Proposals）

## 概要

Marubo AI のソースコード全体を分析し、現在「実装されていない」「考慮が漏れている」
「仕様が曖昧である」箇所を以下の4観点から洗い出しました。

1. UI/UX の空白
2. エッジケースと異常系
3. セキュリティと権限
4. ビジネスロジックの矛盾・パフォーマンス

---

## Gap Analysis テーブル

| ID | 指摘箇所・機能 | 現在の実装状況（課題） | システムへの影響 | 最適な改善提案（アーキテクチャ・コードレベルで具体的に） | 優先度 |
|---|---|---|---|---|---|
| GAP-01 | ログイン後のルーティング | ログイン成功時、ロールに関わらず常に `/admin/allowlist` にリダイレクト。生徒がログインしても管理画面に飛ばされ、403 エラーになる | 生徒ユーザーのUXが著しく悪い。ログイン直後に権限エラーが表示される | ログイン後に `/api/sync-user` のレスポンス（role, allowedEmailStatus）を評価し、`role === 'staff'` なら `/admin/allowlist`、`role === 'student'` かつ `status === 'active'` なら `/chat` にルーティングする。`status === 'pending'` なら待機画面を表示 | **高** |
| GAP-02 | Next.js Middleware による認証ガード | `middleware.ts` が存在しない。認証ガードはすべてクライアントサイド（AllowlistGuard）またはAPIルートハンドラ内で実装 | 未認証ユーザーが `/chat`、`/admin/*` などのページの HTML/JS バンドルをダウンロード可能。ページが一瞬表示されてからリダイレクトされるフラッシュ現象が発生 | Next.js Middleware (`middleware.ts`) を追加し、`/chat`、`/reports`、`/admin/*` へのアクセス時に Supabase セッション cookie を検証。未認証なら `/login` に 302 リダイレクト。クライアント側 AllowlistGuard は二重チェックとして維持 | **高** |
| GAP-03 | ログアウト機能 | 明示的なログアウトボタン・機能が実装されていない。`supabase.auth.signOut()` の呼び出し箇所がない | ユーザーが意図的にログアウトできない。ブラウザのストレージを手動でクリアする必要がある。共有端末でのセキュリティリスク | ヘッダーまたはサイドバーにログアウトボタンを追加。`supabase.auth.signOut()` → セッションクリア → `/login` にリダイレクト。レポート画面には「ログアウト」リンクがあるが、実際の処理は未実装 | **高** |
| GAP-04 | セッション有効期限の管理 | トークンの有効期限チェックやリフレッシュ処理が明示的に実装されていない。`onAuthStateChange` で監視しているが、期限切れ時の具体的な処理が不明 | 長時間操作のないタブでトークンが失効し、次のAPI呼び出しで突然 401 エラーが発生。チャット中にセッション切れが起きると入力中のテキストが失われる可能性 | Supabase の `onAuthStateChange` イベントで `TOKEN_REFRESHED` を処理。`SIGNED_OUT` イベント時はモーダルで「セッションが切れました。再ログインしてください」と表示し、入力中データを localStorage に退避してからログイン画面にリダイレクト | **高** |
| GAP-05 | チャット画面のオフライン/ネットワークエラー対応 | ネットワーク切断時の処理が未実装。ストリーミング中に接続が切れた場合のリカバリ機能がない | ネットワーク不安定な環境（学校のWi-Fiなど）で、送信したメッセージが消失したり、AIの回答が途中で途切れたりする。中高生の利用環境では特に発生しやすい | (1) `navigator.onLine` + `online`/`offline` イベントでネットワーク状態を監視し、オフラインバナーを表示。(2) 送信失敗時はメッセージを `localStorage` に保存し、再接続後にリトライボタンを表示。(3) ストリーミング中断時は「回答が途中で中断されました」と表示し、再送信ボタンを提供 | **高** |
| GAP-06 | 管理画面の確認ダイアログ | すべての確認ダイアログが `window.confirm()` / `window.alert()` を使用。ブラウザネイティブのダイアログで、カスタマイズ不可 | (1) 視覚的に貧弱でプロダクト品質に見えない。(2) 非同期操作の結果待ちができない（alertは同期的にブロック）。(3) モバイルでの見た目が不統一 | React ベースのモーダルコンポーネント（`ConfirmDialog`）を作成。`@headlessui/react` の `Dialog` または shadcn/ui の `AlertDialog` を使用。非同期結果の表示、ローディングインジケータ、複数行メッセージに対応 | **中** |
| GAP-07 | 会話の削除機能 | 会話の削除 API・UI が存在しない。`DELETE /api/conversations/[id]` が未実装 | ユーザーが不要な会話を整理できない。会話が増え続けるとサイドバーが長くなり、UXが悪化。GDPR等のデータ削除要求に対応できない | (1) `DELETE /api/conversations/[id]` API を実装（RLS で本人のみ）。(2) 会話サイドバーの各項目にスワイプ or コンテキストメニューで「削除」を追加。(3) 確認ダイアログ付き。(4) 関連する messages, attachments も CASCADE DELETE | **中** |
| GAP-08 | 添付画像の署名URL有効期限切れ対応 | 署名URLの有効期限は10分。長時間開いたままのチャット画面では署名URLが期限切れになり、画像が表示されなくなる | ユーザーが過去の会話を再閲覧する際、10分以上前に取得した署名URLが無効になり、画像が壊れて表示される。リロードすれば治るが、UXが悪い | (1) 画像コンポーネントに `onError` ハンドラを追加し、失効検知時に自動で再署名を試行。(2) `IntersectionObserver` で画面内に入った画像のみ署名URLを取得（遅延署名）。(3) 署名URLに残り時間を表示しない（バックグラウンドで自動更新） | **中** |
| GAP-09 | 会話タイトルの自動生成ロジック | 会話タイトルがユーザーの最初のメッセージの先頭部分をそのまま使用。長いメッセージの場合は途中で切れる | タイトルが長すぎてサイドバーのレイアウトが崩れる可能性。「こんにちは」のような短い挨拶がタイトルになると、後から会話を見つけにくい | (1) 会話の最初のやり取り（ユーザー質問 + AI回答）から LLM で短いタイトルを自動生成（`onFinish` のタイミング、非同期）。(2) 生成コストを抑えるため gpt-4o-mini の短いプロンプトで20文字以内のタイトルを生成。(3) フォールバック: LLM生成失敗時は現行の先頭切り出しを使用 | **低** |
| GAP-10 | /admin ページのプレースホルダー | `/admin` ページがプレースホルダーテキストのみ。管理機能へのナビゲーションハブとして機能していない | スタッフが `/admin` にアクセスしても有用な情報がなく、各管理画面のURLを直接知っている必要がある | `/admin` をダッシュボード化: (1) 各管理機能へのカードリンク（許可リスト管理、権限管理、会話検索、レポート管理）。(2) サマリー統計（アクティブユーザー数、今月の質問数、保留中の申請数）。(3) スタッフ認証ガードで保護 | **中** |
| GAP-11 | /chat-test ページの本番露出 | `/chat-test` が認証なしでアクセス可能。開発・テスト用のページが本番環境で公開されている | 未認証ユーザーがチャット機能を（トークンなしで）試行でき、エラーログが増える。セキュリティ監査で指摘される可能性 | (1) `NODE_ENV === 'production'` の場合は 404 を返す。(2) または `middleware.ts` でブロック。(3) ベストプラクティス: 開発用ページは `app/(dev)/chat-test/` グループルートに移し、本番ビルドから除外 | **高** |

## 4. 提案を踏まえた将来のアーキテクチャ展望

### 4.1 短期的改善効果（高優先度の実装後）

上記の高優先度 8 項目を実装することで、以下の改善が見込まれます。

**UX 改善**:
- ログイン後のルーティング修正（GAP-01）とログアウト機能（GAP-03）により、ユーザーの基本的な認証フローが完成。現在は「ログインしたら管理画面に飛ぶ」という生徒にとって不自然な挙動が解消される。
- モバイル対応（GAP-16）により、中高生の主要デバイスであるスマートフォンでの利用体験が大幅に向上。会話履歴へのアクセスが可能になる。
- ネットワークエラー対応（GAP-05）により、学校のWi-Fi等の不安定な環境でもメッセージが消失しない安心感を提供。

**セキュリティ強化**:
- Middleware 認証ガード（GAP-02）により、未認証ユーザーが保護ページの JavaScript バンドルをダウンロードすることを防止。SSR レベルでの保護が追加される。
