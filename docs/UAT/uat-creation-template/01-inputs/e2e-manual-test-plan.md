# E2E 手動テスト計画書

本書では、ブラウザで手動実行する最小限のエンドツーエンドシナリオを定義する。
自動テスト（Vitest）ではカバーできないブラウザ依存の動作・認証フロー・UI 表示を検証する。

> **目的**: デプロイ前にクリティカルパスが動作することを確認する。
> **頻度**: 本番デプロイ前、または大きな機能変更後に1回実施。

---

## 前提条件

### 環境セットアップ

1. `.env.local` に必要な環境変数が設定されていること（`.env.example` 参照）
2. Supabase プロジェクトが起動していること（ローカル or リモート）
3. `pnpm dev` で開発サーバーが起動していること
4. 以下の確認コマンドがすべてパスしていること:

```bash
pnpm lint        # ESLint エラーなし
pnpm typecheck   # TypeScript エラーなし
pnpm test        # Vitest 全件パス
```

### テストデータ

| 項目 | 値 |
|------|-----|
| 生徒用 Google アカウント | `allowed_email` に `active` で登録済みのメール |
| スタッフ用 Google アカウント | `app_user.role = 'staff'` のメール |
| 未登録メール | `allowed_email` に存在しないメール |

## シナリオ 1: 生徒 — ログイン → 質問 → 回答 → 履歴確認

**対応する受け入れ基準**: S-01, S-05, S-06, S-08, S-09, S-10

### 手順

| # | 操作 | 期待結果 | 確認 |
|---|------|----------|------|
| 1-1 | ブラウザで `/login` にアクセス | ログイン画面が表示される | [ ] |
| 1-2 | 「Google でログイン」をクリック | Google 認証画面にリダイレクトされる | [ ] |
| 1-3 | 許可リストに `active` で登録済みのメールでログイン | `/chat` にリダイレクトされ、チャット画面が表示される | [ ] |
| 1-4 | テキストボックスに「1+1は？」と入力して送信 | AI がストリーミングで回答を表示する | [ ] |
| 1-5 | テキストボックスに「$x^2 + y^2 = r^2$ を説明して」と入力して送信 | 回答中の数式が KaTeX でレンダリングされる | [ ] |
| 1-6 | サイドバーの会話一覧を確認 | 直前の会話がタイトル・日付付きで表示される | [ ] |
| 1-7 | 「＋」ボタンをクリック | 新しい空の会話画面になる | [ ] |
| 1-8 | サイドバーから先ほどの会話を選択 | 過去のメッセージが時系列で正しく表示される | [ ] |
