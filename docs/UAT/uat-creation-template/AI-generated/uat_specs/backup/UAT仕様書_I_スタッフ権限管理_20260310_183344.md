## 2. カテゴリ概要

スタッフ権限管理カテゴリは、特権スタッフ（`GRANT_ALLOWED_EMAILS` に登録された 2 名のみ）が `/admin/grant` でスタッフ権限の付与・解除を行う機能を対象とする。権限付与・解除の操作、権限外ユーザーによる操作拒否、スタッフ一覧と audit_grant 操作履歴の表示を検証する。テスト優先度は「高」（運用上の必須機能）。

**重要な前提事項:**
- 本カテゴリのテストは `GRANT_ALLOWED_EMAILS` に登録された特権スタッフアカウントが必要
- 特権スタッフのメールアドレス: `maru.juku.maru@gmail.com`（塾長）または `yuu.kw5.sea@gmail.com`
- テスト用のダミー生徒アカウント（権限付与対象）を用意すること

## 4. 統合テストシナリオ

### IT_I_001: スタッフ権限の付与から解除までのライフサイクル

| 項目 | 内容 |
|------|------|
| **シナリオID** | IT_I_001 |
| **目的** | スタッフ権限の付与・解除と、対象ユーザーのアクセス制御変化を検証 |

**シナリオ手順:**

1. 特権スタッフとしてログインし `/admin/grant` にアクセスする
2. `uat_grant_target@gmail.com` にスタッフ権限を付与する（TC_I_001）
3. `uat_grant_target@gmail.com` が再ログインし、`/admin` にリダイレクトされることを確認する（TC_A_002 との連携）
4. 特権スタッフとして再度 `/admin/grant` にアクセスし、スタッフ一覧と操作履歴を確認する（TC_I_007）
5. `uat_grant_target@gmail.com` のスタッフ権限を解除する（TC_I_003）
6. `uat_grant_target@gmail.com` が再ログインし、`/chat` にリダイレクトされることを確認する（生徒ロールに戻っている）

**期待結果:** 権限付与・解除が正しく機能し、対象ユーザーの動作に反映される

## 5. 備考

- `GRANT_ALLOWED_EMAILS` は環境変数で管理されており、Vercel の環境変数設定で確認できる（サーバーサイドのみ、`NEXT_PUBLIC_*` ではない）
- スタッフ権限付与後、対象ユーザーは必ず**再ログイン**が必要（JWT の `app_metadata.role` が更新されるため）
- 自動テスト（`pnpm test`）で 11 件のテストケースが実施済み（grant/revoke + 認可/バリデーション/監査ログ）
- テスト後のクリーンアップ: テスト用に付与したスタッフ権限（`uat_grant_target@gmail.com` 等）は必ず解除すること
