## 2. カテゴリ概要

認証・アカウント管理カテゴリは、Supabase Auth（Google OAuth）を使用したユーザーログイン・ログアウト・セッション管理を対象とする。許可リスト（`allowed_email` テーブル）の `status` に基づいてアクセス可否を判定し、ロール（`student` / `staff`）に応じてリダイレクト先を制御する。本カテゴリはシステム全体のセキュリティ基盤であり、テスト優先度は「最高」。

**前提環境:**
- テスト用 Google アカウントが複数用意されていること（active生徒 / active スタッフ / pending / revoked / 未登録）
- テスト環境の URL: `https://marubo-ai.vercel.app`（または検証環境 URL）

### A-01: Google アカウントによるログイン（active ユーザー）

#### TC_A_001: active 生徒アカウントでのログインと /chat へのリダイレクト（正常系）

| 項目 | 内容 |
|------|------|
| **テストケースID** | TC_A_001 |
| **業務ID** | A-01 |
| **テスト区分** | 正常系 |
| **優先度** | 最高 |
| **前提条件** | テスト対象メールアドレス（student_test@gmail.com 等）が `allowed_email` テーブルに `status='active'`, `label='テスト生徒'` で登録済み。未ログイン状態でブラウザを開いている |

**操作手順:**

1. ブラウザで `https://marubo-ai.vercel.app/login` にアクセスする
2. ログイン画面が表示されることを確認する
3. 「Google でログイン」ボタンをクリックする
4. Google OAuth 認証画面が表示されるので、`status='active'` の生徒アカウントで認証する
5. 認証完了後、システムに戻ってくることを確認する
6. URL が `/chat` に遷移することを確認する

**期待結果:**

| 確認ポイント | 期待値 | 確認方法 |
|------------|--------|---------|
| リダイレクト先 URL | `/chat` | アドレスバーで確認 |
| チャット画面の表示 | チャット入力欄・サイドバーが表示される | 画面確認 |
| ヘッダーのログアウトボタン | 表示されている | 画面確認 |
| 残り質問数の表示 | ヘッダーに「残り N/100」が表示される | 画面確認 |
| `app_user` レコードの作成 | Supabase ダッシュボードで `app_user` テーブルに対象メールのレコードが存在する | DB 確認（任意） |

## 5. 備考

- Google OAuth の実際の認証には Google アカウントが必要。テスト用アカウントを事前に準備すること
- Supabase Dashboard で `allowed_email` テーブルを直接編集することで、各ステータスのテストデータを作成できる
- `TC_A_008` のセッション失効テストは、長時間放置（Supabase の JWT 有効期限: デフォルト 1 時間）でも再現可能だが、Cookie 削除の方が迅速にテストできる
- セキュリティヘッダーの確認は K カテゴリ（TC_K_008）で実施するため、本カテゴリでは省略
