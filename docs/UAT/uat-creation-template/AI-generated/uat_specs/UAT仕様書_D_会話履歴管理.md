## 2. カテゴリ概要

会話履歴管理カテゴリは、生徒がチャット画面のサイドバーで過去の会話を一覧表示・選択・削除し、新規会話を開始する機能を対象とする。モバイル端末でのドロワー表示も含む。RLS により本人の会話のみ表示されることも検証する。テスト優先度は「中」。

**前提条件:**
- active 生徒としてログイン済みであること
- 過去の会話履歴が複数件存在すること（TC_B_001 等で事前作成）

#### TC_D_004: 他の生徒の会話 URL への直接アクセス（異常系）

| 項目 | 内容 |
|------|------|
| **テストケースID** | TC_D_004 |
| **業務ID** | D-02 |
| **テスト区分** | 異常系（RLS 検証） |
| **優先度** | 最高 |
| **前提条件** | 2つの生徒アカウントが存在し、一方の生徒（生徒A）の会話 ID を取得済み |

**操作手順:**

1. 生徒A の会話 ID を DevTools > Network で確認する（`/api/conversations/` の後のUUID）
2. 別のブラウザまたはシークレットモードで生徒B としてログインする
3. `https://marubo-ai.vercel.app/api/conversations/{生徒AのconversationId}` に直接 API リクエストを送信する（または対応するフロントエンドの URL にアクセスする）
4. 生徒B から生徒A の会話が取得できないことを確認する
5. 続けて、生徒B のセッションで `DELETE /api/conversations/{生徒AのconversationId}` を DevTools > Network または curl 等で直接呼び出し、403 エラーが返ることを確認する

**期待結果:**

| 確認ポイント | 期待値 | 確認方法 |
|------------|--------|---------|
| RLS によるアクセス拒否（GET） | 他の生徒の会話は取得できない（404 または空の結果、または 403 エラー） | DevTools > Network または画面確認 |
| 他ユーザー会話の削除拒否（DELETE） | 他の生徒の会話を削除しようとすると 403 エラーが返る | DevTools > Network 確認 |
| 自動テスト検証 | RLS の動作は自動テスト（`pnpm test`）で証明済み | テスト実行結果参照 |

## 5. 備考

- D-04 の会話削除では `messages` と `attachments` も CASCADE DELETE されるため、削除後に会話詳細 API を呼び出すと 404 が返ることを確認すること（DevTools > Network で確認可能）。TC_D_007 の期待結果に「推奨」確認として追記済み
- 他のユーザーの会話削除の 403 確認は TC_D_004 の手順5で実施すること（D-04 スコープ定義の「他のユーザーの会話を削除しようとすると 403 エラー」に対応）
- RLS の詳細な検証は自動テスト（`pnpm test`）で実施済み。本 UAT では手動での基本動作確認に留める
- モバイルテストは実機（iOS/Android）または Chrome DevTools の Device Toolbar で実施する
- 会話タイトルの自動生成規則（「先頭発話の 30〜50 文字」）は実装依存であり、設計書での明確な定義の確認が推奨される
