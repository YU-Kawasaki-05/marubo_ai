# AI-generated ディレクトリについて

## 概要

このディレクトリには、UAT仕様書自動作成ツールが生成した成果物が格納されます。

## 自動生成されるファイル

### 1. UATスコープ定義書.md

**作成タイミング**: フェーズ1（uat0-make-scope-agent）

**内容**:
- プロジェクト概要
- UAT対象業務の一覧（100%網羅）
- 業務カテゴリ構造

```

└── UATスコープ定義書.md
```

## ファイルの読み方

### UAT仕様書の構成

各UAT仕様書には以下の情報が含まれます:

1. **業務概要**: 業務の目的と範囲
2. **テストシナリオ**: エンドツーエンドのテストシナリオ
3. **テストケース**: 詳細なテストステップ
   - 前提条件
   - テスト手順
   - 期待結果
   - テストデータ
4. **非機能要件テスト**: 性能、セキュリティ、ユーザビリティ
5. **例外処理テスト**: エラーケース、境界値テスト

### 検証結果の読み方

検証結果には以下の評価が含まれます:

- **❌ 要改善**: 重大な問題があり、大幅な改善が必要
- **⚠️ 改善推奨**: 改善の余地があり、中程度の修正が推奨
- **✅ 良好**: 品質が高く、軽微な調整のみ

### バージョン管理

改善が行われるたびにバージョン番号が更新されます:

- **v1.0**: 初回作成（フェーズ2）
- **v1.1**: 1回目の改善（フェーズ4、1回目）
- **v1.2**: 2回目の改善（フェーズ4、2回目）
- **v2.0**: メジャーな改善（大幅な変更時）

## 利用方法

### 1. 成果物の確認

実行完了後、以下のファイルを確認してください:

1. `UAT仕様書_統合レポート.md` - 全体のサマリー
2. `uat_specs/` - 各カテゴリのUAT仕様書

### 2. 業務網羅率の確認

`UAT仕様書_統合レポート.md` で業務網羅率100%が達成されているか確認してください。

### 3. テストケースのレビュー

各カテゴリのUAT仕様書をレビューし、必要に応じて手動で調整してください。

### 4. バックアップの活用

改善前の内容を確認したい場合、`uat_specs/backup/` 内のファイルを参照してください。

## 注意事項

- このディレクトリ内のファイルは自動生成されます
- 手動で編集した場合、次回実行時に上書きされる可能性があります
- 重要な変更は別の場所にバックアップしてください
- 改善回数を増やすと、バックアップファイルが増加します

## よくある質問

### Q: 生成されたファイルを編集してもいいですか？

A: 可能ですが、次回実行時に上書きされる可能性があります。
   重要な変更は別のディレクトリにコピーして保存してください。

### Q: バックアップファイルを削除してもいいですか？

A: はい、不要になったバックアップは削除可能です。
   ただし、改善履歴が必要な場合は残しておいてください。

### Q: 一部のカテゴリだけ再生成できますか？

A: 現在のバージョンでは全カテゴリを再生成します。
   部分的な再生成が必要な場合は、エージェントを直接呼び出してください。
